Bagian 1

Ringkasan Sistem

CubingCoach menilai performa satu kali solve rubik 3x3 menggunakan logika fuzzy metode Mamdani. Sistem menerima tiga input, yaitu kecepatan putaran (TPS), jumlah gerakan, dan rasio jeda, yang diambil otomatis dari smart cube QiYi melalui Bluetooth atau dimasukkan secara manual. Ketiga input diolah melalui fuzzifikasi, inferensi dengan 27 aturan, agregasi, dan defuzzifikasi metode centroid, sehingga menghasilkan skor performa 0–100, kategori (pemula, menengah, mahir), serta rekomendasi latihan.

Input 3 variabel TPS · Jumlah gerakan · Rasio jeda dari smart cube atau manual
Proses Fuzzy Mamdani fuzzifikasi → inferensi → komposisi → agregasi → centroid
Output Skor 0–100 kategori + rekomendasi latihan

Bagian 2

Mengapa Logika Fuzzy

Penilaian seperti "cepat", "efisien", atau "sering berhenti" tidak punya batas yang tegas. Dua solver dengan TPS 3,9 dan 4,1 praktis sama cepatnya, tetapi logika biasa (crisp) dengan satu garis batas akan memasukkan mereka ke dua kategori yang berbeda, seolah-olah selisih 0,2 putaran per detik adalah perbedaan besar.

Logika fuzzy mengatasi hal ini dengan membolehkan satu nilai menjadi anggota beberapa kategori sekaligus, masing-masing dengan derajat keanggotaan antara 0 dan 1. Cara ini mirip dengan cara seorang pelatih menilai muridnya: "sudah cukup cepat, tapi masih sering berhenti", bukan sekadar lulus atau tidak lulus.

Topik ini juga dekat dengan kehidupan sehari-hari. Rubik adalah hobi yang populer, dan banyak pemain kesulitan mengetahui kelemahannya secara objektif. Data dari smart cube memberikan angka, dan logika fuzzy mengubah angka tersebut menjadi penilaian dan saran latihan yang mudah dipahami.

Mengapa Mamdani, bukan Sugeno atau Tsukamoto? Output Mamdani berupa himpunan linguistik (pemula, menengah, mahir) yang mudah ditafsirkan, dan aturannya ditulis dalam bahasa sehari-hari ("JIKA cepat DAN efisien DAN jeda sedikit MAKA mahir"), sehingga mudah disusun dan divalidasi bersama pakar cubing.

Bagian 4

Metode Mamdani

Perhitungan berjalan dalam lima tahap berurutan:

  1. 1FuzzifikasiNilai tegas → derajat keanggotaan.
  2. 2Inferensiα tiap aturan, AND = MIN.
  3. 3Komposisiα terbesar per himpunan output (MAX).
  4. 4AgregasiPotong setinggi α, gabungkan (MAX).
  5. 5DefuzzifikasiCentroid → satu skor.

1 Fuzzifikasi

Setiap nilai input dimasukkan ke fungsi keanggotaan trapesium [a, b, c, d] milik tiap himpunan. Hasilnya derajat keanggotaan μ antara 0 (sama sekali bukan anggota) dan 1 (anggota penuh).

μ(x) = 0                    jika x < a atau x > d
     = 1                    jika b ≤ x ≤ c
     = (x − a) / (b − a)    jika a ≤ x < b     (sisi naik)
     = (d − x) / (d − c)    jika c < x ≤ d     (sisi turun)

Jika a = b, himpunan berbentuk bahu kiri (nilai ≤ a bernilai 1). Jika c = d, berbentuk bahu kanan (nilai ≥ d bernilai 1). Input di luar semesta dibatasi (clamp) ke batas minimum/maksimum.

2 Inferensi (implikasi MIN)

Setiap aturan memakai operator DAN. Dalam Mamdani, DAN dihitung dengan nilai minimum, karena sebuah aturan hanya sekuat premis terlemahnya.

α_i = min(μ_TPS, μ_Gerakan, μ_Jeda)

3 Komposisi (MAX)

Beberapa aturan bisa mengarah ke himpunan output yang sama. Yang dipakai adalah aturan terkuat.

α_k = max(α_i untuk semua rule yang MAKA-nya k),   k ∈ {pemula, menengah, mahir}

4 Agregasi (MAX)

Setiap himpunan output dipotong setinggi α-nya, lalu ketiga potongan digabung menjadi satu kurva.

μ_agg(z) = max_k( min(α_k, μ_k(z)) )

5 Defuzzifikasi (centroid)

Kurva gabungan diubah menjadi satu angka, yaitu titik beratnya. Program menghitungnya secara diskrit pada z = 0, 0.5, …, 100. Kategori akhir adalah himpunan output dengan μ(z*) terbesar.

z* = Σ(z · μ_agg(z)) / Σ μ_agg(z)        (jika Σμ = 0, skor = 0)

Bagian 6

Basis Aturan

Setiap aturan berbentuk JIKA TPS = … DAN Gerakan = … DAN Jeda = … MAKA Skor = …. Ada 3 × 3 × 3 = 27 kombinasi. Konsekuen tiap aturan disusun dengan sistem poin kualitas berikut, sehingga setiap aturan punya alasan yang bisa dijelaskan:

Bagian 7

Aturan Rekomendasi Latihan

Selain skor, program memberi saran latihan berdasarkan derajat keanggotaan input. Sebuah saran muncul jika μ himpunan "lemah" mencapai ambang 0.5. Dalam satu kelompok, hanya saran pertama yang terpenuhi yang ditampilkan.

Bagian 8

Contoh Perhitungan Manual

Kasus: TPS = 3,5; Gerakan = 70; Jeda = 20%.

Fuzzifikasi

  • TPS 3,5: lambat = 0; sedang = 1 (3 ≤ 3,5 ≤ 4); cepat = 0
  • Gerakan 70: efisien = 0; normal = 1 (65 ≤ 70 ≤ 75); boros = 0
  • Jeda 20: sedikit = (25 − 20)/(25 − 10) = 0,333; sedang = (20 − 10)/(25 − 10) = 0,667; banyak = 0

Inferensi (rule aktif)

  • R14: sedang ∧ normal ∧ sedang → menengah, α = min(1; 1; 0,667) = 0,667
  • R15: sedang ∧ normal ∧ sedikit → menengah, α = min(1; 1; 0,333) = 0,333

Komposisi

α_menengah = max(0,667; 0,333) = 0,667; α_pemula = 0; α_mahir = 0

Agregasi

Himpunan menengah [25, 45, 55, 75] dipotong pada 0,667. Titik potong sisi naik: z = 25 + 0,667 × 20 = 38,33. Sisi turun: z = 75 − 0,667 × 20 = 61,67.

Defuzzifikasi

Bentuk agregasi simetris terhadap z = 50, sehingga centroid = 50. Versi diskrit (langkah 0,5) di program: z* = 2444,167 / 48,883 = 50,00.

Hasil

Skor 50 → μ_menengah(50) = 1 → kategori Menengah.
